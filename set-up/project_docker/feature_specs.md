# Feature Specs

## Overview
This document outlines the planned features and specifications for the Docker MCP RAG Army system, with an emphasis on orchestrator/AI-driven onboarding and automation.

## Features
- Modular agent containers
- Orchestrator with unified endpoint
- Agent-to-agent (A2A) protocol endpoints
- Agent card metadata for discovery
- Shared Docker network for communication
- Secure .env-based configuration
- Logging and monitoring
- Extensible agent templates
- **AI-driven Onboarding:** Repo discovery, auto-cloning, RAG analysis, .env onboarding, and automated compose/config generation

## AI/Orchestrator-Driven Onboarding Flow
- On first setup, the orchestrator or onboarding agent:
  - Discovers or clones required repos (with user input or auto-discovery)
  - Uses RAG to analyze repo structure (Dockerfile, .env.example, etc.)
  - Prompts user for required secrets or custom values (e.g., API keys)
  - Auto-generates .env files for each agent/container
  - Writes/updates docker-compose.yml and all agent config files
  - Sends a test prompt to each new agent; displays the response to the user
  - Benchmarks each agent (latency, correctness, resource usage); results and a final 'ready' message are shown to the user
  - Supports batch onboarding of multiple agents
- All changes are persisted and versioned for reproducibility

## Planned Specs
- Each agent exposes FastAPI endpoints for tool invocation and A2A
- Orchestrator discovers agents and aggregates responses
- Docker Compose manages all services
- .env file for secrets and API keys (auto-generated by onboarding)
- Agent initialization logic is scriptable and supports non-interactive (env-driven) mode

## Future Extensions
- Integration with Kubernetes for scaling
- Pluggable authentication/authorization modules
- Advanced monitoring and analytics
